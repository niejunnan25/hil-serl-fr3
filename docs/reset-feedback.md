# 复位路径与手柄完成提醒（2026-09-21）

当前工作台配置：`reset_clear_z: 0.15`、`reset_feedback: true`。

1. 保持当前 XY 和姿态，垂直拔出到机器人基坐标系 Z=0.150 m。如果开始时已经更高，第一段不会下降。
2. 回到 `RESET_POSE`：Z=0.150 m、固定向下姿态；保留 XY ±6 mm 随机化。
3. 两段测量确认到位、稳定，且夹爪/关节检查通过后，Xbox 震动一次，持续 800 ms；强/弱电机为 `0xD000` / `0xB000`。
4. 震动期间持续只读检查夹爪、关节、力、低速与位姿稳定性；结束后再检查，并等待两路新图像，最后打开 episode、开始采集。提醒期间仍是 `resetting`：连续视频和墙钟计时继续，不产生环境 steps；Learner 不开始新的参数更新，已在执行的更新可能完成。

稳定检测要求连续至少 0.5 秒，位置相对窗口起点漂移不超过 0.5 mm，姿态漂移不超过 0.005 rad，关节速度不超过 0.03 rad/s。第一段快速完成误差为 4 mm，第二段为 6 mm；姿态误差均为 0.04 rad。第二段静止在约 5 mm 跟踪误差时不再固定等满 8 秒。两段都不再使用原有 12 mm / 0.12 rad 的放宽条件。第一段针对 0.150 m 目标的最低允许实测 Z 为 0.146 m（同时须满足整体位置、姿态和稳定性条件）；未达到时不开始横移。等待过久或卡住不能降低此门槛。力、关节、动作增量和超时保护保留。

提醒通过 Linux evdev 的 FF_RUMBLE 实现；只发现唯一支持震动的 Microsoft Xbox，不写死 event 编号，不抓占输入设备，也不发手柄按键。停止/异常后清理 effect；手柄缺失或提醒失败会保留错误并阻止本条采集。每个提醒检查点同时重新读取机器人状态；测量异常、漂移超过 0.5 mm / 0.005 rad、关节速度超过 0.03 rad/s 或力超限时，中止提醒并禁止采集，不补发第二次提醒。正常循环的睡眠间隔最多 50 ms，另外受状态请求和系统调用耗时影响。

工作台显示“1/2 垂直拔出”“2/2 回到随机起点”“复位完成 · 手柄震动 0.8 秒”和“确认状态与新图像”。提醒从 reset 生命周期触发，刷新网页不会重复触发。

两路图像使用共同的提醒后时间边界，必须等待采集返回时间戳推进；总等帧预算 2 秒，最终图像距检查时刻不得超过 0.25 秒。若其中一路延迟使先取得的帧变旧，则刷新整对图像。超时、相机故障或期间机器人状态变化时，不进入 episode。复用同一物理相机的分类器/策略图像共用一帧。帧索引、时间边界及最终机器人状态采集时间写入 reset 证据。这是软件采集返回时间的一致性检查，不宣称硬件曝光同步。

新训练、续训、独立评估的每个新启动采用当前复位高度及提醒开关，写入各自 `attempts/.../config.json`、环境快照和源代码指纹。历史 run 配置和录像不改写。旧 Actor/Learner 必须退出，工作台重新加载配置；不会绕过源码指纹检查。已保存模型的图像、动作和网络配置仍从历史记录读取。

验证：使用模拟时钟、状态反馈、进程和 evdev 设备离线覆盖运动、限幅、稳定/抖动、卡住、取消、单次提醒、观测时序、训练门以及启动/评估快照。审阅发现的拔出不足、提醒期间状态变化、缓存旧图、单路相机卡住和异常清理均有回归用例。此次部署没有执行真实机械臂运动；0.150 m 的实际拔出余量与实际复位耗时仍须通过现场首次运行核对。
